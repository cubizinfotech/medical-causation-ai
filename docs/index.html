Legal Research AI

Two attorney tools in one application: medical causation research, and investigation of an opposing expert. This is legal research assistance. It is not a hospital system and it does not diagnose patients.

Local demonstration ready

Medical Causation Analysis

Purpose

Help an attorney study whether a trauma or accident medically contributed to an injury or a disease. The application uses the firm’s indexed documents and the AI model that has been configured. The attorney reviews the result. The software does not issue a medical opinion.

User input

The attorney enters the case: what happened, the injury or condition, and the history they choose to include. The form can show an uploaded file. In the current demo, that file is not sent into the analysis.

Workflow

  • The attorney submits the case.
  • The application searches the indexed knowledge base.
  • The AI model writes a structured analysis from the passages it was given.
  • The screen shows progress, then the finished result.
  • If evidence is missing, the result says so. It does not fill the gap with an invented citation.

Output

An on-screen report with the analysis, supporting and opposing evidence, citations, and cross-examination questions. Past cases stay in history.

Major features

  • Guided case intake
  • Background processing with visible progress
  • Search over the private knowledge base
  • Citation checks
  • Saved case history

Expert Witness Investigation

Purpose

Help an attorney prepare to question an opposing medical expert. The investigation collects what public and approved sources can support, and it keeps a clear record when something cannot be verified.

User input

The expert’s name and medical specialty.

Workflow

  • The attorney starts one investigation.
  • The application continues through profile, education, licenses, publications, legal mentions, public pages, and related checks.
  • The attorney does not approve every step.
  • If a source is unavailable, the investigation continues and records that.
  • The application does not invent a degree, a license, or a lawsuit.

Output

A finished page and a Microsoft Word report. The report includes a summary, findings, discrepancies, source links, limitations, and cross-examination questions based on the collected record. When the evidence is thin, the questions stay limited to what was found.

Major features

  • A single start action for the full investigation
  • Live progress
  • Source-by-source status, including “not found” and “unavailable”
  • Discrepancy notes
  • A downloadable Word report

Local development overview

Developers run the database and the job queue in Docker on a laptop. The website is at http://localhost:3000. No DigitalOcean server is required. No paid API account is required.

  • Expert research uses sample records, not live paid databases.
  • Email is written to the application log. It is not sent to a university or an agency.
  • A live medical-causation analysis is the optional step that needs a chat model. A free tier is enough.

Step-by-step setup is in the demonstration guide.

Production architecture overview

When the client is ready, the same application can run on one DigitalOcean server. The website, the API, the database, and the job queue run in containers. A reverse proxy provides HTTPS for the domain. Research vendors and outbound email stay off until the client confirms them. Backups are a later decision. They are not installed as part of the current plan.

The server guide is digitalocean.md.

AI provider

The screens ask one shared AI service for help. That service can be pointed at different model companies without rewriting the products. The model is only allowed to discuss evidence the application already retrieved. Extra facts from the model are discarded.

Research provider

Expert research goes through a catalog of sources. A source might later be a free public site, a paid account, or a manual check. In local development none of those outside services are called. If a source has nothing, the report says the information was not found. That is not treated as proof that the expert lacks a credential.

Report generation

Medical Causation Analysis shows its report in the browser. Expert Witness Investigation also builds a Microsoft Word document from the collected findings. The two products share the Word builder and keep their own document layouts. Text from a restricted database is not copied into the Word file.

Deployment overview

  • Today: develop and demonstrate on a local computer.
  • Later: one Ubuntu server on DigitalOcean, Docker, a domain, and HTTPS.
  • Database and Redis stay private to that server.
  • Paid research keys and production email are optional until approved.
